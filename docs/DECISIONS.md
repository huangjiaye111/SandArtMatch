# 项目冻结决策

## 项目基础

- 项目类型：微信小游戏。
- 游戏引擎：以当前Cocos Creator项目版本为准。
- 开发语言：TypeScript。
- 屏幕方向：竖屏。
- 设计分辨率：750 × 1334。

## 战斗布局

- 上部：沙画区域。
- 中部：传送带区域。
- 下部：待选沙桶区域。
- 底部：道具栏。
- 默认传送带槽位：6个。
- 桶池布局：2行4列。

## 核心规则

- 玩家点击沙桶后，沙桶进入传送带。
- 沙桶自动吸收暴露的同色沙粒。
- 沙桶装满后离场并释放槽位。
- 三个同色沙桶可以合成。
- 三个桶的容量可以不同。
- MVP中合成默认不要求相邻。
- 玩法随机数必须可复现。
- 玩法代码禁止使用Math.random()。
- 槽位满不代表立即失败。
- 必须等待吸沙、重力、合成和离场完成后检测死局。

## 技术原则

- 核心玩法使用纯TypeScript实现。
- 核心规则不得依赖Cocos Node或Component。
- UI不得直接修改核心战斗数据。
- 玩家操作统一交给BattleStateMachine。
- 沙粒使用二维逻辑网格。
- 视觉粒子与逻辑沙粒分离。

## 首个MVP包含

- 沙粒网格；
- 确定性重力；
- 暴露沙粒检测；
- 沙桶；
- 传送带；
- 三桶合成；
- 自动吸沙；
- 胜负判定；
- 死局判定；
- 撤回；
- 竖屏战斗UI；
- 测试关卡。

## 首个MVP不包含

- 商店；
- 签到；
- 排行榜；
- 每日挑战；
- 正式广告SDK；
- 社交系统。

## TASK021 正式关卡与首页选关

- 当前正式 Catalog 只包含 `level-001`，其 `nextLevelId` 为 `null`。
- Home 内嵌动态关卡选择，不使用独立 `LevelSelect` 场景。
- 正式流程为 `Boot -> Home -> Battle`；Victory 和 Deadlock 只提供 Replay 与 Home。
- 保留 `LevelCatalog`、`ProgressStore`、`GameSession` 和统一 `GameNavigator` 作为后续扩展架构。
