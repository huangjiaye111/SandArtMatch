# 《流沙消消》微信小游戏策划案 V0.4

## 竖屏版玩法与全界面 UI 设计稿

---

# 一、产品概述

## 1.1 产品定位

《流沙消消》是一款以“流沙物理表现、颜色收集、沙桶合成和有限槽位管理”为核心的休闲益智微信小游戏。

玩家通过选择不同颜色和容量的沙桶，将沙桶放入传送带。沙桶自动吸收沙画底部暴露的同色沙粒，装满后离场。三个相同颜色的沙桶可以合成更大的沙桶，并提高吸沙速度。

玩家需要在有限传送带槽位中安排桶的进入顺序，最终清空整幅沙画。

## 1.2 平台与屏幕方向

* 运行平台：微信小游戏
* 屏幕方向：竖屏
* 基准设计尺寸：750 × 1334
* 推荐适配比例：9∶16至9∶20
* 操作方式：单手点击
* 单局时间：1～4分钟
* 核心用户：消除、排序、收纳、倒水、螺丝和解压类游戏用户

## 1.3 核心体验

```text
观察底部可收集颜色
→选择沙桶
→沙桶进入传送带
→自动吸收同色沙粒
→沙粒流动并重新分布
→沙桶装满离场或三桶合成
→清空沙画
```

主要策略压力来自：

* 传送带槽位有限；
* 部分沙桶暂时无法吸沙；
* 沙桶容量不同；
* 沙画颜色暴露顺序不断变化；
* 特殊桶会改变正常选择顺序。

# 二、竖屏整体视觉结构

## 2.1 设计原则

竖屏版本需要解决两个问题：

第一，沙画区域不能过小，否则玩家无法判断底部暴露颜色。

第二，沙桶池不能占据过多高度，否则会压缩沙画空间。

因此，战斗界面采用“上方沙画、中部传送带、下方桶池、底部道具栏”的四段式结构。

## 2.2 基准屏幕分区

以750 × 1334为基准：

| 区域    |      高度范围 |   占比 |
| ----- | --------: | ---: |
| 顶部状态栏 |     0～110 |  约8% |
| 沙画主区域 |   110～700 | 约44% |
| 传送带区域 |   700～885 | 约14% |
| 沙桶选择区 |  885～1190 | 约23% |
| 道具操作区 | 1190～1334 | 约11% |

全面屏设备需要根据微信安全区域动态调整顶部和底部边距。

## 2.3 全局安全区

```text
顶部安全边距：系统状态栏高度＋20px
底部安全边距：系统手势区高度＋16px
左右安全边距：24px
```

重要按钮不得贴近刘海、圆角或底部手势区域。

# 三、核心玩法规则

## 3.1 沙画系统

沙画逻辑上是一张由颜色编号构成的二维网格。

每个逻辑格包含：

```text
位置坐标
颜色编号
是否存在沙粒
是否正在移动
是否暴露
是否可被吸收
```

表现层不需要为每颗沙粒创建真实刚体。

推荐方案：

```text
逻辑层：64×64至128×128二维网格
表现层：粒子、贴图抖动、流线和填充动画
```

## 3.2 沙粒运动规则

沙粒移动优先级：

```text
正下方为空
→向下移动

正下方被占用，左下为空
→向左下移动

正下方被占用，右下为空
→向右下移动

左下和右下都为空
→根据固定随机种子选择方向
```

使用确定性随机种子，确保：

* 相同操作产生相同结果；
* 撤回后结果可复现；
* 自动求解器和实际关卡一致；
* 测试缺陷可以稳定复现。

## 3.3 暴露沙粒判定

建议使用“底部空气连通”判定。

```text
从沙画底边空格开始洪泛搜索
→获得与外部连通的空气区域
→与空气区域接触的沙粒视为暴露沙粒
→匹配颜色的桶可以吸收这些沙粒
```

这种方式可以支持凹槽、洞穴和侧向滑落。

## 3.4 沙桶系统

每个沙桶包含：

| 字段   | 说明                    |
| ---- | --------------------- |
| 颜色   | 决定可吸收的沙粒颜色            |
| 容量   | 最大可收集沙粒数              |
| 当前量  | 已经吸收的沙粒数量             |
| 吸收速度 | 单位时间吸收量               |
| 合成等级 | 普通桶、一级合成桶等            |
| 特殊类型 | 普通、钥匙、锁定、问号、冰冻等       |
| 当前状态 | 待选择、进入、等待、吸收、合成、完成、离场 |

桶容量为关卡配置值，不限制为固定等级。

示例：

```text
95、120、130、260、330、400、650、800、1000
```

## 3.5 传送带系统

默认槽位数量：

```text
新手关：6格
普通关：6格
困难关：5格
高难关：4～5格
广告扩展：临时增加1格
```

沙桶进入传送带后占用一个槽位。

处理顺序：

```text
点击沙桶
→检查空槽
→沙桶进入传送带
→检查合成
→执行吸沙
→执行沙粒重力
→检查桶完成
→检查胜负
```

## 3.6 三桶合成

基础条件：

```text
传送带中出现三个相同颜色的沙桶
```

原型规则：

* 不要求容量相同；
* 不要求合成等级相同；
* 默认不要求相邻；
* 允许不同容量桶合成；
* 是否允许半满桶合成由关卡规则配置。

合成结果：

```text
新桶容量
= 三个原桶剩余容量之和

新桶已吸收量
= 三个原桶已吸收量之和

新桶吸收速度
= 普通桶速度 × 合成倍率
```

建议倍率：

| 等级    | 速度倍率 |
| ----- | ---: |
| 普通桶   |  1.0 |
| 一级合成桶 |  1.8 |
| 二级合成桶 |  2.8 |

合成桶放置在三个原桶中最靠前的位置，并释放另外两个槽位。

## 3.7 胜利条件

```text
沙画剩余沙粒数量为0
并且所有沙粒动画结束
```

## 3.8 失败条件

必须同时满足：

```text
传送带没有空位
没有桶能够吸收当前暴露沙粒
没有桶即将装满离场
没有可触发的三桶合成
没有沙粒正在移动
没有特殊机制正在结算
```

传送带刚满时不能立即判负。

# 四、核心战斗界面 UI

## 4.1 战斗主界面布局

```text
┌────────────────────────────┐
│ 返回      第18关       金币 │
│          进度条             │
├────────────────────────────┤

│          沙画区域           │
│                            │
│       沙粒流动与吸收         │
│                            │
├────────────────────────────┤
│ 槽位 3/6                   │
│ [桶][桶][空][空][桶][空]    │
│          传送带             │
├────────────────────────────┤
│      待选择沙桶区域          │
│ [桶][桶][锁][桶]            │
│ [桶][? ][桶][桶]            │
├────────────────────────────┤
│  撤回      提示      加槽位  │
└────────────────────────────┘
```

## 4.2 顶部状态栏

位置：屏幕顶部安全区下方。

高度：约90px。

内容：

左侧：

* 返回按钮；
* 点击后弹出暂停界面；
* 不直接退出，防止误操作。

中间：

* 当前关卡号；
* 沙粒清理进度条；
* 可显示“已清理68%”。

右侧：

* 金币数量；
* 设置按钮可选；
* 正式对局中不建议显示过多货币入口。

排版建议：

```text
返回按钮：64×64
关卡标题：字号32～36
进度条：宽260～320，高18～24
金币区：图标36，数字字号26
```

## 4.3 沙画区域

位置：顶部状态栏下方。

推荐尺寸：

```text
宽度：660～700px
高度：500～580px
```

沙画外框采用浅色画框或玻璃容器表现。

区域组成：

* 沙画内容层；
* 沙粒逻辑层；
* 沙粒表现粒子层；
* 吸沙流线层；
* 教学手势层；
* 特殊物体层。

底部需要预留约40～60px的透明吸沙出口区域，用于显示沙粒流向传送带。

沙画比例可根据关卡图案变化，但逻辑碰撞区域保持固定。

## 4.4 传送带区域

位置：沙画区与桶池之间。

高度：约170～190px。

内容：

* 槽位数量提示；
* 沙桶槽位；
* 传送带底座；
* 当前工作位置；
* 合成特效区域。

推荐排版：

```text
槽位尺寸：92×110
槽位间距：8～12
6个槽位总宽：约620～660
```

槽位状态：

| 状态   | 表现        |
| ---- | --------- |
| 空槽   | 浅灰虚线框     |
| 普通桶  | 正常桶模型     |
| 吸沙中  | 桶上方出现流沙线  |
| 即将装满 | 桶身轻微闪烁    |
| 可合成  | 三个桶出现同色描边 |
| 合成中  | 向中间吸附、旋转  |
| 冻结   | 蓝色冰层覆盖    |
| 锁定   | 锁链或锁图标覆盖  |

槽位计数显示：

```text
3 / 6
```

建议放在传送带左上角，不遮挡沙桶。

## 4.5 桶池区域

位置：传送带下方。

高度：约270～310px。

桶池建议使用2行4列布局。

```text
第一行：4个桶
第二行：4个桶
```

单桶点击区域：

```text
宽度：145～155px
高度：120～135px
```

每个桶显示：

* 桶体颜色；
* 容量数字；
* 特殊状态图标；
* 锁、钥匙、问号或冰冻状态；
* 被推荐选择时的高亮。

容量数字建议显示在桶体正面，使用白色或深色高对比描边。

桶池滚动策略：

MVP阶段不使用上下滚动，始终只显示当前可选择的6～8个桶。

后续关卡若待选桶较多，采用“队列补位”：

```text
玩家选择一个桶
→该位置空出
→后续桶从右侧或下方补入
```

不建议使用自由滚动列表，会增加误触。

## 4.6 道具栏

位置：屏幕底部安全区上方。

高度：约120～140px。

三个核心道具：

| 道具  | 作用            |
| --- | ------------- |
| 撤回  | 恢复最近一次稳定操作前状态 |
| 提示  | 高亮推荐沙桶        |
| 加槽位 | 本关临时增加一个传送带槽位 |

排版：

```text
左：撤回
中：提示
右：加槽位
```

每个按钮尺寸：

```text
按钮区域：150×100
图标：52～64
文字字号：24
数量角标：24～30
```

道具数量为0时：

* 显示视频图标；
* 点击后打开激励广告确认弹窗。

# 5.6 新手教学界面

教学采用半透明遮罩＋局部高亮，不单独跳转页面。

## 教学步骤示例

第一步：

```text
高亮蓝色沙桶
提示：点击蓝色沙桶，将它放入传送带。
```

第二步：

```text
高亮传送带槽位
提示：沙桶会占用一个传送带位置。
```

第三步：

```text
高亮三个同色桶
提示：三个相同颜色的沙桶会自动合成。
```

第四步：

```text
高亮沙画底部
提示：沙桶会自动吸收底部暴露的同色沙粒。
```

教学气泡应避开被指示目标。

教学期间禁止点击无关区域。

# 七、特殊桶 UI 表现

## 7.1 问号桶

桶池状态：

* 桶身显示大问号；
* 不显示颜色；
* 容量可以显示，也可以隐藏。

揭晓时：

* 问号旋转；
* 桶身颜色渐变出现；
* 播放短促揭晓音效。

## 7.2 钥匙桶

桶身右上方显示钥匙图标。

建议规则：

```text
钥匙桶装满离场
→获得一把钥匙
→自动解锁一个锁定桶
```

UI表现：

* 钥匙飞向锁；
* 锁链断裂；
* 被锁桶恢复正常颜色。

## 7.3 锁定桶

锁定状态：

* 桶体降低亮度；
* 覆盖金属锁图标；
* 点击时轻微抖动；
* 提示“需要先获得钥匙”。

## 7.4 冰冻桶

表现：

* 半透明冰层；
* 冰面裂纹；
* 显示解冻进度数字，例如`2/3`。

解冻时：

* 冰层碎裂；
* 碎片快速消散；
* 桶恢复正常点击状态。

## 7.5 万能桶

表现：

* 彩虹渐变桶身；
* 可以吸收任意颜色；
* 容量通常较小；
* 吸沙时桶身转变为当前吸收颜色。

# 八、界面交互反馈

## 8.1 点击沙桶

```text
按下：缩小至95%
抬起：回弹至105%
进入传送带：沿曲线飞入
落位：轻微弹跳
```

## 8.2 吸沙反馈

* 对应颜色沙粒轻微闪烁；
* 沙粒形成流线进入沙桶；
* 桶内填充高度实时上涨；
* 容量数字同步下降或显示进度。

推荐显示方式二选一：

方案A：

```text
已吸收量 / 总容量
320 / 800
```

方案B：

```text
剩余容量
480
```

建议使用方案B，与桶容量数字更直观一致。

## 8.3 桶装满反馈

* 桶体放大；
* 出现完成光圈；
* 桶盖闭合；
* 向传送带出口移动；
* 释放槽位。

## 8.4 合成反馈

```text
三个桶描边发光
→向中间吸附
→旋转合并
→出现更大沙桶
→播放低频“咚”反馈
```

合成动画总时长建议0.5～0.8秒。

## 8.5 错误点击反馈

传送带已满时点击沙桶：

* 沙桶左右摇晃；
* 传送带槽位闪红一次；
* 显示轻提示“传送带没有空位”。

不弹出阻断式弹窗。

# 九、竖屏适配规范

## 9.1 长屏设备

对于高度超过16∶9的设备，额外空间优先分配给：

1. 沙画主区域；
2. 沙桶区域上下间距；
3. 底部安全边距。

不能简单拉伸沙桶和按钮。

## 9.2 短屏设备

对于接近16∶9的设备：

* 缩短顶部状态栏；
* 减少沙画上下留白；
* 桶池高度压缩；
* 道具文字可缩小；
* 不减少点击区域。

## 9.3 平板设备

平板继续保持竖屏。

主内容最大宽度限制：

```text
最大逻辑宽度：850～900px
```

超出部分使用背景填充，避免所有UI横向拉伸。

# 二、全局 UI 视觉规范

## 2.1 视觉方向

整体风格建议采用：

```text
明亮
柔和
轻立体
低压力
高色彩识别度
```

不建议采用：

* 过暗背景；
* 高饱和霓虹色；
* 复杂机械传送带；
* 大量金属纹理；
* 细小文字；
* 过度写实沙粒。

核心视觉重点应始终是：

```text
沙画图案
沙粒流动
沙桶颜色
传送带剩余槽位
```

## 2.2 色彩层级

### 背景层

主界面背景建议使用低饱和浅色：

```text
米白
浅奶黄
浅天蓝
浅薄荷绿
```

背景不能与沙桶颜色竞争。

### 功能层

主操作按钮使用高辨识度暖色，例如：

```text
橙黄色
珊瑚橙
暖绿色
```

次级按钮使用：

```text
浅蓝
浅灰
米白
```

危险操作使用少量红色，仅用于：

* 重新开始确认；
* 删除；
* 放弃关卡；
* 网络错误中的严重状态。

### 沙桶颜色

沙桶颜色应与沙粒颜色保持一致，但桶体可以增加明暗变化。

建议至少支持：

```text
红
橙
黄
绿
青
蓝
紫
粉
棕
黑
白
```

必须保证色弱情况下仍可通过以下方式区分：

* 桶身纹理；
* 颜色编号；
* 图形符号；
* 明暗差异；
* 轮廓样式。

## 2.3 字体规范

建议使用微信小游戏可稳定加载的系统字体或授权字体。

字号参考：

| 用途    |    字号 |
| ----- | ----: |
| 页面大标题 | 40～48 |

# 三、全局页面结构

游戏界面分为以下三类。

## 3.1 独立页面

独立页面会替换当前场景主体：

* 启动页；
* 首页；
* 关卡选择；
* 战斗界面；
* 图鉴；
* 签到；
* 商店；
* 设置；
* 每日挑战。

弹窗显示时，背景界面保留但不可交互：

* 暂停；
* 失败；
* 通关；
* 重新开始确认；
* 道具说明；
* 购买确认；
* 广告确认；
* 网络错误；
* 隐私授权。

## 3.3 非模态提示

不会阻断游戏：

* Toast文字提示；
* 桶容量不足提示；
* 槽位已满提示；
* 奖励获得提示；
* 道具数量变化；
* 网络恢复提示。

# 五、沙画区域详细规范

## 5.1 沙画容器

推荐尺寸：

```text
宽：690
高：530～560
```

容器包括：

```text
外框
背景底板
逻辑沙粒层
视觉沙粒层
障碍层
吸沙效果层
教学高亮层
```

## 5.2 沙画对齐方式

不同图案尺寸不同时，不进行拉伸。

采用：

```text
保持宽高比
水平居中
底部对齐
```

沙画底部必须靠近吸沙出口。

## 5.3 沙画边框

边框视觉可以采用：

* 透明玻璃框；
* 浅木质画框；
* 简化白色容器；
* 卡通展示柜。

MVP建议采用透明玻璃框，容易适配多种主题。

## 5.4 吸沙出口

沙画底部设置一个视觉出口区域。

推荐尺寸：

```text
宽：180～260
高：40～60
```

该区域不是唯一逻辑出口，但用于集中表现吸沙流线。

吸收沙粒时：

```text
暴露沙粒
→沿短路径移动到沙画底部
→汇聚到出口
→流向对应沙桶
```

## 5.5 沙画状态

### 稳定状态

* 沙粒无明显位移；
* 玩家可以选择桶；
* 当前暴露颜色可以轻微闪烁。

### 下落状态

* 沙粒执行重力；
* 允许预点击可选桶，但不立即结算；
* 玩家点击会进入输入队列。

### 清空状态

* 剩余沙粒为0；
* 等待最后粒子特效结束；
* 进入通关弹窗。

# 六、传送带 UI 详细规范

## 6.1 传送带整体结构

传送带包含：

```text
槽位计数
槽位容器
桶实例
传送带背景
出口动画
合成特效
```

推荐尺寸：

```text
宽：680
高：150
```

## 6.2 槽位排布

6槽标准布局：

```text
单槽宽：96
单槽高：112
槽间距：10
总宽：626
```

居中排列。

若关卡为5槽：

* 单槽尺寸不变；
* 整体居中；
* 不拉宽槽位。

若临时增加至7槽：

* 将单槽缩至84～88；
* 保持数字可读；
* 只在本关内使用。

## 6.3 槽位状态

### 空槽

表现：

* 浅色虚线框；
* 内部透明；
* 不播放动画。

### 被占用

表现：

* 桶体完整显示；
* 容量数字清晰；
* 桶底对齐。

### 当前吸沙桶

表现：

* 桶上方出现流沙轨迹；
* 桶边缘轻微高亮；
* 填充液位上升。

### 即将完成

当剩余容量低于总容量10%时：

* 桶体轻微脉冲；
* 容量数字闪烁一次；
* 不使用持续强闪。

### 可合成

三个同色桶满足条件时：

* 同色描边；
* 三桶之间出现连线；
* 停留0.15秒后自动执行合成。

### 冻结

* 覆盖冰层；
* 降低饱和度；
* 不参与普通吸沙。

### 锁定

锁定桶原则上不应进入传送带。

若特殊关卡允许锁定桶占槽，则：

* 桶体变暗；
* 显示挂锁；
* 不参与吸沙和合成。

## 6.4 桶容量显示

推荐使用“剩余容量”。

示例：

```text
800
```

吸收100后显示：

```text
700
```

优点：

* 玩家可以直接判断还需要多少沙；
* 桶满时数字自然归零；
* 合成后的容量变化明显。

容量数字不能低于24px。

## 6.5 传送带动画

桶进入：

```text
桶池位置
→缩放至90%
→沿贝塞尔曲线飞入空槽
→回弹至100%
```

桶移动：

```text
槽位释放
→后方桶自动向前补位
```

建议移动时长：

```text
0.2～0.35秒
```

桶离场：

```text
桶盖闭合
→向右上或右侧出口移动
→淡出
```

# 七、沙桶选择区详细规范

## 7.1 标准布局

桶池采用：

```text
2行 × 4列
```

每个桶卡位：

```text
宽：150
高：125
```

间距：

```text
横向：15
纵向：12
```

## 7.2 桶卡片结构

每个桶卡片包含：

```text
点击热区
桶体
颜色表现
容量数字
特殊图标
锁定遮罩
推荐高亮
剩余次数或层数
```

## 7.3 点击热区

点击热区应大于桶视觉模型。

例如：

```text
视觉桶：105 × 100
点击热区：145 × 120
```

防止小屏误触。

## 7.4 桶池补位

推荐采用固定槽位补位：

```text
玩家点击第2个桶
→第2个位置空出
→后续桶依次左移
→队列末尾补入新桶
```

补位动画时长：

```text
0.15～0.25秒
```

补位期间允许继续点击，但点击对象必须锁定到实例ID，不能按屏幕位置判断。

## 7.5 桶状态

### 普通可选

* 正常饱和度；
* 点击有缩放反馈。

### 当前推荐

* 外圈发光；
* 上下浮动；
* 持续2秒。

### 暂不可选

可能原因：

* 槽位已满；
* 桶被冻结；
* 桶被锁定；
* 正处于教学限制。

表现：

* 降低亮度；
* 点击后抖动；
* 弹出短提示。

### 问号桶

显示：

```text
？
```

可隐藏：

* 颜色；
* 容量；
* 特殊类型。

首版建议只隐藏颜色，容量仍显示。

### 钥匙桶

桶右上角显示钥匙图标。

钥匙桶装满后，钥匙从桶飞向锁定桶。

### 冰冻桶

显示冰层和解冻数字：

```text
2
```

表示还需要2次触发才能解冻。

# 二十九、竖屏适配实现

## 29.1 Canvas适配

推荐：

```text
设计分辨率：750 × 1334
Fit Width：开启
Fit Height：根据场景判断
```

首页和普通页面可以优先Fit Width。

战斗界面应使用自定义布局脚本，根据实际屏幕高度分配区域。

## 29.2 高度分配算法

```ts
const safeHeight = screenHeight - topInset - bottomInset;

const hudHeight = clamp(safeHeight * 0.07, 78, 96);
const toolBarHeight = clamp(safeHeight * 0.10, 120, 150);
const bucketPoolHeight = clamp(safeHeight * 0.22, 270, 330);
const conveyorHeight = clamp(safeHeight * 0.14, 175, 210);

const sandAreaHeight =
  safeHeight -
  hudHeight -
  toolBarHeight -
  bucketPoolHeight -
  conveyorHeight;
```

沙画区域最低高度建议：

```text
480
```

若低于480：

* 缩短桶池上下边距；
* 缩短HUD；
* 缩短传送带空白；
* 不缩小点击热区。

## 29.3 平板适配

平板设备：

```text
内容最大宽度：900
背景全屏铺满
核心内容居中
左右增加装饰
```

不得把六个槽位拉伸到整个平板宽度。

# 三十二、UI验收清单

## 战斗界面

* 沙画宽度不低于屏幕宽度85%；
* 六个槽位可同时完整显示；
* 桶容量数字在普通手机上清晰可读；
* 桶池每个点击区域不小于120 × 100；
* 道具按钮不进入底部手势区；
* 槽位满时有明确反馈；
* 合成时不会遮挡沙画主体；
* 提示高亮不会与冻结或锁定状态混淆。

## 页面适配

* 9∶16设备无遮挡；
* 9∶19.5设备无大面积无效空白；
* 平板不横向过度拉伸；
* 刘海屏顶部按钮不被遮挡；
* 底部手势区域不影响操作。

## 弹窗

* 弹窗主按钮始终可见；
* 弹窗打开时背景不可点击；
* 同一时间只显示一个模态弹窗；
* 通关和失败不会同时出现；
* 视频失败不扣除奖励机会；
* 重新开始必须二次确认。
